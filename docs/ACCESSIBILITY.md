# Accessibility v1

本文件用于约束移动端 App 的可访问性实现方式，目标不是做一套复杂无边界规范，而是在**不增加重依赖、不破坏当前最小闭环**的前提下，让工业决策类 App 在日常使用、放大字体、单手点击和辅助阅读场景下更稳定。

## 1. 先结论，后细节

每个页面优先保证用户先看到“稳不稳、风险高不高、要不要处理”，再展开指标、趋势和解释内容。不要把大量细碎信息堆在首屏，也不要让用户必须横向扫读多个小字区块后才能得到结论。

## 2. 字体放大时优先保证不炸布局

涉及标题、指标、状态标签、按钮组的区域，优先使用可换行、可堆叠、可纵向退化的布局，不依赖单行塞满。设计默认支持系统字体放大后的主要阅读路径仍可完成，宁可页面变长，也不要出现大面积裁切、重叠和溢出。

## 3. 触控区域优先于视觉紧凑

高频按钮、策略确认入口、告警处理入口、返回入口等可点击控件，优先保证足够的点击面积和留白，不追求“看起来塞得更多”。工业决策产品的移动端更强调低误触和可确认，而不是信息密度极限。

## 4. 关键动作必须有文字，不只靠颜色或图标

像高风险、需确认、已失败、执行中、已回执这类状态，必须至少由“图标 + 文本”或“文本 + 状态样式”共同表达，不能仅依赖颜色深浅区分。对色觉差异、屏幕亮度变化和室外环境，都要保留足够可读性。

## 5. Tooltip 与 Semantics 只补关键路径

当前阶段不追求全量无障碍覆盖，优先给关键操作补充 `Tooltip` 或 `Semantics`：例如策略采用、人工表态、重规划、告警确认、审计入口、回放入口。原则是少而准，让辅助阅读和长按提示服务于真实操作，而不是把所有元素都堆上说明文字。

## 6. 表单与确认流优先降低犯错概率

凡是涉及 override / guidance / veto、执行确认、参数切换、回滚等动作，应优先采用更容易理解和更容易点击的交互形式。相比紧凑控件，允许使用更大的选项卡、卡片式单选、分步确认和明确的状态反馈，以减少误操作。

## 7. 趋势、区间和解释内容要支持分段阅读

风险区间、后果列表、反事实解释、事件说明等内容，不要做成连续密集大段文本。优先拆成标题、短句、要点、分组区块，让用户在移动端能够快速扫读并抓住重点，不必长时间盯着屏幕细读。

## 8. 所有新增页面默认按“最小可访问闭环”验收

每次新增或修改页面，至少自查四件事：
- 在模拟器里能正常运行；
- 字体放大后核心路径仍可完成；
- 关键按钮足够好点；
- 高风险动作有明确确认与状态反馈。

当前阶段可访问性的目标不是一次性做到完整标准合规，而是形成一套**可持续执行、低成本落地、适合工业决策移动端**的基础规则。

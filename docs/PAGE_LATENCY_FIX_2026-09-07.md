# 页面延迟修复与本机验证（2026-09-07）

影响目录：移动端 `dt_mobile_app`，共享 API `../port-dt-multi`。

## 根因与修复

- 首页、态势、策略、重规划重复执行 500 操作的工作流基准。态势、策略和重规划只读取所需业务证据；完整工作流校验按报告、配置、实现文件的内容哈希复用，变化或缺失时重新校验或报错，失败不返回旧成功结果。业务证据哈希与实时审计仍逐次验证。
- 移动 API 的同步磁盘工作放入 FastAPI 同步路由工作线程；强化学习能力查询的首次运行库导入改在线程内执行，避免堵塞事件循环。
- 首次进入子页面原本构建全部四个页面。现按访问记录初始化，避免点击态势时启动隐藏策略页的强化学习查询。
- 态势初次读取、后台更新、连续手动刷新共享正在进行的请求；策略刷新同样合并。成功数据无需等待偏好缓存写盘才展示。
- 修复加载占位卡只有高度、宽度收缩成竖条的问题。

## 实测

同一本机共享服务，HTTP 请求整体耗时；不是屏幕首帧耗时或现场 SLA。

| 接口 | 修复后连续三次（毫秒） |
| --- | --- |
| 态势 | 37.7 / 20.4 / 20.0 |
| 首页共享状态 | 2629.1 / 22.5 / 20.6 |
| 策略候选 | 81.9 / 79.4 / 76.4 |
| 告警 | 3.3 / 2.5 / 2.4 |
| 审计校验 | 2.4 / 2.4 / 2.6 |

修复前态势单次 2777.3 毫秒。首页首次完整证据校验仍需约 2.6 秒，后续复用校验结果。

重启后并发请求强化学习能力、态势和健康检查：运行库冷加载 12434.8 毫秒，态势 648.0 毫秒，健康检查 625.8 毫秒，证明冷加载不再把其他请求阻塞到完成。
